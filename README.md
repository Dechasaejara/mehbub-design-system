# Agency Design Platform

A multi-brand, multi-platform design-system monorepo for a design and software development agency.

## What is included

- Shared design tokens and semantic themes.
- Web components for React and Next.js.
- React Native component primitives.
- Client brand examples (`client-alpha`, `client-beta`).
- A small client-project scaffolding CLI.
- Storybook documentation starter.
- Next.js dashboard starter.
- Changesets and GitHub Actions release workflows.

## Architecture principles

1. **Core is brand-neutral.** Shared components consume semantic tokens, never client-specific hex values.
2. **Brands are configuration.** Client identity lives in separately versioned brand packages/configuration.
3. **Platform rendering is native.** Web and React Native share design contracts and token meaning, not DOM/CSS implementations.
4. **Client projects pin versions.** Updates are deliberate, reviewed dependency upgrades.
5. **Ownership is explicit.** Agency core, client brand assets, and project deliverables are kept in separate locations and governed by contract.

## Requirements

- Node.js 20+
- pnpm 9+
- Git
- GitHub account and a private repository for publishing

## Quick start

```bash
corepack enable
pnpm install
# Commit the generated pnpm-lock.yaml
pnpm build
pnpm test
```

Run individual applications/packages:

```bash
pnpm --filter @agency/docs dev
pnpm --filter @agency/dashboard dev
pnpm --filter @agency/cli build
```

## Use web components

```tsx
import { AgencyProvider, Button, Card, Input } from "@agency/react";
import "@agency/react/styles.css";
import { clientAlphaTheme } from "@agency/brand-client-alpha";

export function ContactPanel() {
  return (
    <AgencyProvider theme={clientAlphaTheme}>
      <Card>
        <Input label="Email" placeholder="you@example.com" />
        <Button>Send inquiry</Button>
      </Card>
    </AgencyProvider>
  );
}
```

The example brand package is a workspace package in this starter. In client applications, install the published packages from GitHub Packages and install the relevant private brand package separately.

## Use React Native components

```tsx
import { AgencyNativeProvider, Button, Card, Input } from "@agency/react-native";
import { clientAlphaNativeTheme } from "@agency/brand-client-alpha/native";

export function ContactScreen() {
  return (
    <AgencyNativeProvider theme={clientAlphaNativeTheme}>
      <Card>
        <Input placeholder="Email address" />
        <Button title="Send inquiry" />
      </Card>
    </AgencyNativeProvider>
  );
}
```

## Create a client starter

```bash
pnpm --filter @agency/cli build
node packages/cli/dist/index.js create-client --name client-new --preset corporate --framework next
```

The CLI creates a starter folder in the current working directory. It does not create GitHub repositories or publish packages automatically.

## Git workflow

- `main`: protected, releasable branch.
- Feature branches: `feat/...`, `fix/...`, `docs/...`.
- Pull requests: require review, checks, and a Changeset for publishable package changes.
- Releases: merge release PR generated by Changesets.

## Publishing

Configure these GitHub repository secrets/permissions:

- `GITHUB_TOKEN` is provided by GitHub Actions.
- Package publishing workflow requires `packages: write`.
- Consumers need a GitHub token with `read:packages` and access to the private package.

Set package names to `@agency/<package>` and publish to GitHub Packages. Before first release, confirm the organization/package visibility and access policies in GitHub.

## Important production work before adopting

This repository is a runnable starter foundation, not a claim of a fully audited production platform. Before broad client use:

- Add comprehensive accessibility and visual regression tests.
- Add native Storybook (React Native Storybook) and Expo example app.
- Add token validation and Style Dictionary build outputs for CSS, TS, and native.
- Add semver compatibility tests and release approval policy.
- Add per-client access controls/repositories for confidential brand assets.
- Review client contracts, IP ownership, licenses, and package access.
- Add real dashboard authentication, authorization, audit logs, and persistence before storing client data.
